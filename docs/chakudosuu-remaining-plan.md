# 着度数の残りの取り込み計画

[jvdata-remaining-plan.md](jvdata-remaining-plan.md) の段階 8 で、着度数の表 (`Chakudosuu`・`ChakudosuuShuukei`) を (対象, 時点) ごとの形にし、JV-Data の CK、JRA-VAN・KOL のマスタの成績を入れた。
この計画は、まだ入れていない次の 2 つを取り込む。

1. JV-Data のマスタ (UM・KS・CH・BN・BR) の成績
2. JRDB の競走馬拡張データ (KKA) の着度数

## 1. 前提

- 着度数の表の形は変えない (2 は別の表を足す)。
  - `Chakudosuu`: 主キーは (Taishou, TaishouId, Nengappi, Kikan, Bunrui)。回数は `Chaku1`〜`Chaku3`・`Chaku4Ika` を必ず、`Chaku4`・`Chaku5`・`Chakugai` は分かるときだけ。
  - `ChakudosuuShuukei`: 主キーは (Taishou, TaishouId, Nengappi, Kikan)。
- 1 レコードぶんの行は `ChakudosuuWriter` (`src/app/daos/ChakudosuuDao.ts`) で集めて保存する。
- 段階ごとにコミットする。段階の終わりに `bun run typecheck` と `bun run lint`、関係するテストファイルだけを実行する。全体の `bun test` は push の前に 1 回。
- テーブルの定義を変えたら、データベースは作り直して取り込み直す (マイグレーションは作らない)。

## 2. 段階 1: JV-Data のマスタの成績

CK とほぼ同じ並びなので、CK の読み取り処理を共通化して使う。時点はどれもデータ作成年月日 (位置 4、8 バイト)。回数は 1 着〜5 着と 6 着以下。

### 2.1 共通化

`JvdataCk` の中の読み取り処理を、`src/app/reader/JRA/JVData/JvdataChakudosuuTool.ts` に移す。

- 馬主・生産者の成績ブロック (60 バイト: 設定年、本賞金合計、付加賞金合計、着回数) を読む処理。CK・BN・BR で使う。
- 騎手・調教師の成績ブロックを読む処理。CK のブロック (1220 バイト) と、KS・CH のブロック (1052 バイト) は並びが違うので、項目の位置を引数で渡す。
- 競馬場別の並び (札幌〜小倉) から場所のコードを引く処理。

### 2.2 UM 競走馬マスタ

対象は馬 (`Taishou.Uma`)、期間は累計。

- 着回数 (各 6 x 3 バイト): 総合 (1106)、中央合計 (1124)、馬場別 7 つ (1142〜: 芝直・芝右・芝左・ダ直・ダ右・ダ左・障害)、馬場状態別 12 (1268〜)、距離別 6 (1484〜: 芝・ダートの 〜1600・1601〜2200・2201〜)。位置は 0 始まり。
  - 距離の区切りは JRA-VAN と同じなので、`kyoriBunrui(track, jravanKyori, i)` を使う。
- 集計: 平地・障害の本賞金・付加賞金・収得賞金の累計 (各 9 バイト、百円)、脚質傾向 (1592)、登録レース数 (1604)。
- `JvdataUm` のコメントの「賞金や着回数の累計、脚質傾向は取り込まない」を直す。

### 2.3 KS 騎手マスタ・CH 調教師マスタ

対象は騎手・調教師。`<本年･前年･累計成績情報>` が 3 つ (各 1052 バイト) 並ぶ。KS は位置 1015、CH は位置 704 から。

- 現役は 本年・前年・累計 の順。引退した人は 引退年・引退前年・累計 の順。
  - 期間は並びのとおり本年・前年・累計にし、年は `ChakudosuuShuukei.Nen` (設定年) で分かるようにする。
  - KOL・JRA-VAN の本年とずれるが、`Nen` を見れば区別できる。引退した人の「本年」が引退年になることを、表のコメントに書く。
- ブロックの中 (0 始まり): 設定年 0、平地本賞金 4、障害本賞金 14、平地付加賞金 24、障害付加賞金 34 (各 10 バイト、百円)、平地着回数 44、障害着回数 80、競馬場別 116 (札幌平地・札幌障害・函館平地 … 小倉障害の 20 個)、距離別 836 (芝・ダート 各 3 区分)。回数はどれも 6 x 6 バイト。
- KS・CH の初騎乗・初勝利・最近の重賞勝利は、引き続き取り込まない。

### 2.4 BN 馬主マスタ・BR 生産者マスタ

対象は馬主・生産者。`<本年･累計成績情報>` が 2 つ (各 60 バイト)。BN は位置 355、BR は位置 423 から。CK の馬主・生産者のブロックと同じ並びなので、2.1 の共通の処理で読む。

- `JvdataBn`・`JvdataBr` のコメントの「本年・累計成績は取り込まない」を直す。

### 2.5 テスト

`test/jvdata.test.ts` に、UM・KS・CH・BN・BR それぞれの成績が、データ作成年月日の時点の着度数になることを足す。

- KS・CH の子項目は仕様書に位置の書式がない (CK の騎手・調教師と同じ) ので、ブロックの先頭からの位置に直接書く。
- 引退した騎手 (設定年が前の年) で、`Nen` が設定年になることも確かめる。
- CK と UM で、同じ馬・同じ日・同じ分類が同じ行になることを確かめる (同じ日に両方が来たとき)。

## 3. 段階 2: JRDB の競走馬拡張データ (KKA)

KKA はまだ取り込んでいないファイル。レースキー (8 バイト) と馬番で出走馬が決まる。回数はどれも 1 着・2 着・3 着・着外 (4 着以下) の 4 つ (各 3 バイト)。

### 3.1 着度数の中身と、入れる先

KKA の着度数は 3 つに分かれる。

| 区分 | 項目 | 意味 | 入れる先 |
|---|---|---|---|
| ※1 | ＪＲＡ成績・交流成績・他成績 | 馬の生涯成績を 3 つに分けたもの。今回のレースによらない | `Chakudosuu` (馬、レースの日、累計) |
| ※2 | 芝ダ障害別・芝ダ障害別距離・トラック距離・ローテ・回り・騎手・良・稍・重・S/M/H ペース・季節・枠 | 馬の成績を、今回のレースの条件で絞ったもの | 新しい表 `ShussoubaJoukenChakudosuu` |
| ※3 | 騎手距離・騎手トラック距離・騎手調教師別・騎手馬主別・騎手ブリンカ・調教師馬主別 | 今回の騎手・調教師などの成績を、今回の条件や組み合わせで絞ったもの | 新しい表 `ShussoubaJoukenChakudosuu` |

※2・※3 は「今回と同じ条件」の成績で、今回のレースが決まって初めて意味を持つ。
重成績には不良を含む、季節・枠の区分が JRDB 独自、など `Chakudosuu` の分類と定義が合わないものも多い。そのため、出走馬ごとの別の表にする。

### 3.2 新しい表

`ShussoubaJoukenChakudosuu` (今回の条件での着度数)

- 主キーは (ShussoubaId, Jouken)。
- `Jouken`: 条件の enum。JRDB の項目と 1 対 1 (芝ダ障害別、芝ダ障害別距離、トラック距離、ローテ、回り、騎手、良、稍、重 (不良を含む)、S ペース、M ペース、H ペース、季節、枠、騎手距離、騎手トラック距離、騎手調教師別、騎手馬主別、騎手ブリンカ、調教師馬主別)。
- 回数: `Chaku1`・`Chaku2`・`Chaku3`・`Chaku4Ika`。全部 0 の条件は行を作らない。
- 表のコメントに、集計の範囲を書く。
  - ※2 は JRA 成績だけ。2007-01-14 までは JRA 成績と交流成績。
  - ※3 は JRA 成績の 3〜5 年分で、月 1 回程度の更新。

※1 は `Chakudosuu` に入れる。

- ＪＲＡ成績 → `ChakudosuuBunrui.Chuuou`
- 交流成績 → 新しい分類 `JrdbKouryuu` (JRA 所属馬の地方交流と海外。KOL の地方交流とは範囲が違うので分ける)
- 他成績 → 新しい分類 `JrdbSonota` (地方所属時などの地方・海外)
- 時点はレースの日。KKA にはレースの日付がないので、開催 (Kaisai) から引く。開催データ (KAA・KAB) や番組データ (BAB・BAC) が先に入っていないと日付が分からない。そのときは ※1 を読み飛ばし、警告ログを出す (※2・※3 は出走馬 ID で入るので影響しない)。

### 3.3 着度数以外の項目

父馬産駒・母父馬産駒の芝連対率・ダ連対率 (％) と連対平均距離 (m) は、出走馬ごとの値なので `ShussoubaYosou` に列を足す。

- `ChichiSankuShibaRentairitsu`・`ChichiSankuDirtRentairitsu`・`ChichiSankuRentaiHeikinKyori`
- `HahaChichiSankuShibaRentairitsu`・`HahaChichiSankuDirtRentairitsu`・`HahaChichiSankuRentaiHeikinKyori`

### 3.4 取り込み処理

- `src/app/reader/JRDB/Kka.ts` を作る。`JrdbShussoubaData` を継承し、出走馬の情報 (`saveShussoubaRelated`) で着度数と産駒の値を保存する。
- `Importer` に `/kka\d+\.txt$/i` を登録する。並びは、出走馬を作る競走馬データ (KYI など) より後にする。
- 項目の位置 (1 始まり): レースキー 1、馬番 9、ＪＲＡ成績 11、交流成績 23、他成績 35、芝ダ障害別 47 から 12 バイトずつ ※2・※3 が 20 個 (調教師馬主別 275 まで)、父馬産駒芝連対率 287、ダ連対率 290、連対平均距離 293 (4 バイト)、母父馬産駒 297・300・303。レコード長 324。
- 回数は `ZZ9` (0 のとき空白) なので、空白は 0 として読む (`ChakudosuuWriter.add` と同じ)。

### 3.5 テスト

- 見本 (`docs/jrdb-spec/Kka/KKA020908.txt`) で取り込み、仕様書の位置の値と突き合わせる (`test/jrdb-records.test.ts`)。
- `test/spec.test.ts` の「読んだ範囲が、すべて仕様書の項目の中に収まる」「仕様書にないコードは…」に KKA が含まれることを確かめる。JRDB の仕様書の項目表の読み取り (`test/spec/`) が KKA に対応していなければ、足す。
- 開催が先に入っていないときに、※1 を読み飛ばして ※2・※3 は入ることを確かめる。

## 4. ドキュメント

- JRDB の取り込み一覧 (取り込むファイルの表があるドキュメント) に KKA を足す。

## 5. 決めること

1. **KS・CH の引退した人の期間**。計画では、並びのとおり本年・前年として `Nen` で区別する。年ごとの期間 (例: 期間 = 年) にする案もあるが、KOL・JRA-VAN の本年・前年と形が変わるので採らない。
2. **KKA の交流成績・他成績を `Chakudosuu` に入れるか**。範囲が KOL の地方交流などと違うので、JRDB 用の分類を足す計画にした。入れずに `ShussoubaJoukenChakudosuu` にまとめる案もある。
3. **KKA の取り込みの順序**。開催がないと ※1 の時点が分からない。Importer の並びで、開催・番組データの後にする。

## 6. 順序

段階 1 (2.1 → 2.2 → 2.3 → 2.4) → 段階 2。2 つの段階は独立していて、入れ替えてよい。
