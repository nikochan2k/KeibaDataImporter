# KOL KD3 データ仕様書と見本データ

`tmp/KOL/` に置いてあったアーカイブを解凍して整理したもの(2026-10-10)。JRDB の [../jrdb-spec/](../jrdb-spec/README.md) と同じ使い方をする。

- 仕様書: `tmp/KOL/仕様書/新データ/kd3frm11.zip` (KD3 フォーマット 第11版)
- 見本データ: `tmp/KOL/サンプルデータ/新データ/kd3_*.lzh` (2007-10-05〜09 の実データの抜粋)

- KD2 の仕様書: `tmp/KOL/仕様書/新データ/kd2frm26.zip` (KD2 フォーマット 第26版, 2010-11-25)。`KD2/spec/` に解凍してある。KD2 の見本データはない(`tmp/KOL/サンプルデータ/旧データ/` は空)。

## 構成

```
KD3/
  spec/            仕様書(HTML, Windows-932)。kol_xxx.html が各データの項目表、table.html はコード表
  kis/ kyu/ syu/   騎手・厩舎・種牡馬データ
  uma/             競走馬データ        (hb071006, ib071006 の 2 本)
  ket5/            5代血統図
  den1/ den2/      出馬表レース・出走馬データ
  ods/ ods2/       予想オッズ(単勝・枠連・馬連 / 馬単・3連複)
  sei1/ sei2/ sei3/ 競走成績レース・出走馬、制裁その他
  com1/            騎手厩舎コメント・次走へのメモ (lb071006, mb071006 の 2 本)
  kod/ kod2/ kod3/ 確定オッズ(単勝・枠連・馬連 / 複勝・ワイド・馬単・3連複 / 3連単)
```

見本ファイルの名前は、元のアーカイブの中の名前(`kol_xxx.kd3`)のまま。同じ種別が複数のアーカイブにあるもの(UMA, COM1)だけ、アーカイブの日付(`_hb071006` など)を付けた。取り込み処理のファイル名パターン(`/kol_uma\.kd3$/`)には一致しないので、テストでは `kol_uma.kd3` の名前で取り込ませている。

## KD2

`KD2/spec/` に KD2 の仕様書(HTML, Windows-932)がある。見本データがないので、KD2 の取り込み処理は、KD3 の見本データを KD2 の並びに組み替えたファイルで確かめている([../kol-kd2.md](../kol-kd2.md))。

## 見本データがないもの

| データ | 仕様書 | 取り込み処理 |
|---|---|---|
| 3代血統図 (`kol_ket`) | `spec/kol_ket.html` | `KolKetKd3` (テストは仕様書から作った 1 レコードで確認) |
| 特別登録レース (`kol_tok1`) | `spec/kol_tok1.html` | **なし** |
| 特別登録出走予定馬 (`kol_tok2`) | `spec/kol_tok2.html` | **なし** |

## 仕様書の癖

- 繰り返しの項目は、先頭の 1 組だけが表に載っていて、途中の項番が飛んでいる(例: UMA の過去走 5 回分・50 回分、オッズの組み合わせ)。表に載っていない範囲は、規則的な繰り返しとして扱う。
- 新設された項目の行は、先頭の列に「新」と書かれている。
- アドレスは 0 始まり。レコード長は、項目表の最後(データ区切り = CR LF)の終わりと一致する。
- ODS2 の末尾の 3 連複 `15-17-18`, `16-17-18` のアドレス(9029, 9034)は 5 バイト間隔になっていて誤記。7 バイトの項目なので、正しくは 9027, 9034(KOD2 の仕様書はそうなっている)。ODS2 の `15-16-18` も 9024 でなく 9020。
- `*`(上限以上)の意味するオッズは、データと賭式ごとに違う(単勝 ODS は 50 倍以上、KOD は 1 万倍以上、3連複は 100 万倍以上、3連単は 1 億倍以上)。

## 使い方

`test/kol.test.ts` が、この仕様書と見本データを使って次を確かめる。ハーネスは `test/spec/kol.ts`。

- 項目表の長さがレコード長と一致する。取り込み処理のレコード長が仕様書と一致する。見本ファイルがレコード長の整数倍で、各レコードが CR LF で終わる。
- 見本データを取り込んで、エラーが出ない。リーダーが読んだ範囲(offset, length)が、すべて仕様書の項目の中(または省略された繰り返しの範囲)に収まる。
- 払戻・オッズの件数や金額、障害の上り時計、5代血統図の牡牝と親子関係など、仕様書の項目と取り込み結果が一致する。
- 過去に誤っていた箇所の回帰テスト([../kol-kd3-review.md](../kol-kd3-review.md) 参照)。

`bun test` では時間のかかる確定オッズ(KOD2・KOD3)の取り込みを省く。すべて取り込むときは `KOL_SPEC_FULL=1 bun test test/kol.test.ts`。
