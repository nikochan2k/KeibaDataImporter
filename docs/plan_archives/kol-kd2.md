# KD2 の取り込み

KOL の第 2 世代フォーマット(KD2, 2010-11-25 発表の第 26 版)の取り込み処理。仕様書は [kol-spec/KD2/spec/](kol-spec/KD2/spec/)、取り込み処理は [src/app/reader/KOL/KD2/](../src/app/reader/KOL/KD2/)。ファイル名は `kol_xxx.kd2`。

## KD3 との違い

KD2 と KD3 は、項目の意味も並びもほとんど同じで、KD3 で項目が増えた分だけアドレスがずれている(KeibaDataAnalizer の KD2/KD3 の Importer も、アドレスが違うだけだった)。仕様書の項目表を突き合わせた結果は次のとおり。

| データ | KD2 | KD3 | 違い |
|---|---|---|---|
| 厩舎 `kyu` / 騎手 `kis` / 種牡馬 `syu` / 競走馬 `uma` / 3代血統図 `ket` | 1248 / 1729 / 2010 / 5166 / 839 | 同じ | 項目のアドレスも桁数も同じ(項目名の空白や「平地」の有無だけ違う) |
| 予想オッズ `ods` / 確定オッズ `kod` | 1504 | 1504 | 先頭のレース情報の Ｊｐｎフラグ の分がずれるだけで、オッズの並び(161 以降)は同じ。KD2 には ods2, kod2, kod3(馬単・3連複・3連単・複勝・ワイド)がなく、払戻は成績データにある |
| 出馬表レース `den1` | 779 | 848 | Ｊｐｎフラグ(73)がない。レース短評・予想展開・予想者名２(350〜417)がない |
| 出馬表出走馬 `den2` | 743 | 1000 | 予想２(255)がない。調教短評・調教本数(694〜726)、スピード指数・ローテーション・休養理由・場所別成績(742〜997)がない |
| 競走成績レース `sei1` | 2756 | 3200 | Ｊｐｎフラグ(74)がない。ラップ・経過・発走状況のブロックが、払戻のあとにある。3連単の払戻がデータ作成年月日のあとにある |
| 競走成績出走馬 `sei2` | 474 | 600 | 末尾の予備フィールドの長さだけ |
| コメント `com1` | 2050 | 3010 | 「前回出走時のコメント」(2011〜2970)がない |
| 特別登録 `tok1` / `tok2` | 2002 / 743 | 2002 / 743 | KD3 でも未対応 |

制裁その他(`sei3`)、5代血統図(`ket5`)は KD2 にない。

## 共通化の方法

- 並びが同じ種別(kyu, kis, syu, uma, ket, ods, kod)は、KD3 の取り込み処理をそのまま使う。[Importer](../src/app/Importer.ts) のパターンを `kol_xxx.kd[23]` にしただけ。
- 位置がずれる種別(den1, den2, sei1)は、取り込み処理を KD3 のアドレスで書いたまま、`KolDataToImport` の `at(kd3アドレス)` で読み替える。KD2 の処理は、KD3 の処理を継承して、読み替えの表(`layout`)とレコード長だけを差し替える。
  - 読み替えの表は [Kd2Layout.ts](../src/app/reader/KOL/KD2/Kd2Layout.ts)。KD3 のアドレスの区間ごとの「ずれ」で、KD2 にない項目は `null`。
  - KD3 の項目の読み取りを、KD2 にない項目だけ `has(アドレス)` で飛ばす(Ｊｐｎフラグ、予想２、調教短評・本数、休養理由、予想展開)。
  - 配当の読み取り位置の表は、`KolLayout.atHaitou` で変換する。
- レコード長だけが違う種別(sei2, com1)は、KD3 の処理を継承して `getBufferLength` だけを差し替える。

KD2 では取り込まれない項目(KD3 にだけある項目)は、`Race.JpnFlag`、`ShussoubaYosou.KolYosou2`、`ShussoubaYosou.Kyakushitsu`(予想展開)、`Shussouba.KyuuyouRiyuu(Code)`、`ShussoubaChoukyou.ChoukyouTanpyou` と本数。KD2 の出馬表に「予想２」(255)がないので、`Shussouba.TorikeshiShubetsu` を予想２から取る分も KD2 では空になる。

## テスト

[test/kol-kd2.test.ts](../test/kol-kd2.test.ts)。KD2 の見本データがないので、KD3 の見本を読み替えの表で KD2 の並びに組み替えたファイル(`.kd2`)を作って取り込む。

1. 項目表のレコード長が、取り込み処理のレコード長と一致する。
2. 読み替えの表が KD2 の仕様書と合っている(循環しないよう、仕様書の項目表だけで確かめる)。
   - KD3 の項目は、読み替えた位置に同じ桁数の KD2 の項目がある。
   - KD2 の項目(予備フィールド以外)はすべて、KD3 の項目を読み替えた位置にある。
   - 読み替えない KD3 の項目と同じ名前の項目が、KD2 にない。
   - 並びが同じ種別は、項目表のアドレス・桁数が全部同じ。
3. 組み替えたファイルを取り込んで、エラーが出ない。リーダーが読んだ範囲が KD2 の仕様書の項目の中に収まる。
4. den1, den2, sei1, sei2, com1 は、KD3 の見本をそのまま取り込んだ結果と、全テーブルの内容が同じ(KD3 にだけある項目の列を除く)。

見本データがないので、実際の KD2 ファイルで確かめたわけではない。実データを入手したら、`docs/kol-spec/KD2/` に置いて、この取り込み結果と照らし合わせたい。
