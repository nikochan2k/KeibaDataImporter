# JV-Data の取り込み処理

`src/app/reader/JRA/JVData/` に、JRA-VAN Data Lab. の JV-Data(Ver.4.9.0.1)のレコードの取り込み処理がある。仕様書は [jvdata-spec/](jvdata-spec/README.md)。
見本データがないので、実データでの確認はしていない。テストは、仕様書の項目名からレコードを作って確かめている。

## ファイルの形

JV-Link が返すレコードを、1 レコード 1 行(末尾は CR LF)で並べたファイル。拡張子は `.jvd`(`Importer` は `/\.jvd$/i` で選ぶ)。
レコード種別(RA、SE、…)が混ざっていてよく、順序も問わない。先頭 2 バイトのレコード種別 ID で `JvData` が振り分ける。

- 取り込み処理のないレコード種別は、debug ログを出して読み飛ばす。
- 末尾の CR LF を除いた長さが仕様書のレコード長 - 2 でないレコードは、warn ログを出して読み飛ばす(CR LF がなくても長さが合えば読む。最後の行に改行がなくてもよい)。
- データ区分 `0`(該当レコード削除)と `9`(レース中止)のレコードは読み飛ばす。ただし重勝式 (WF) の `9` は重勝式の中止なので、読み飛ばさずに残す。

## 取り込まないもの

- 速報系(WH 馬体重、WE 天候馬場状態、AV 出走取消・競走除外、JC 騎手変更、TC 発走時刻変更、CC コース変更)。
- RA: 変更前の値(グレード、距離、トラック、発走時刻)、競走名の副題・カッコ内・欧字、競走条件(年齢別)、前 3・4 ハロン、後 4 ハロン、コーナー通過順位、レコード更新区分。
- SE: 変更前の負担重量・騎手、服色標示、1 着馬(相手馬)情報、後 4 ハロン、獲得付加賞金、マイニング予想、脚質判定。馬番が 0 の出走馬(出走馬名表、馬番が不明の海外レース)。
- UM: 賞金や着回数の累計、脚質傾向。BN: 法人格有の名前、本年・累計成績。HN: 馬名半角カナ(内国産は馬名と同じ、外国の繁殖馬にはない)。BR: 法人格有の名前、本年・累計成績。KS・CH: 初騎乗・初勝利・最近の重賞勝利、成績の集計。YS: 重賞案内。
- データ区分 1(中間)のオッズ。何度も提供される値なのに、時刻の列がなく、1 つの行に重ねてしまうため。

## 設計

JRA-VAN の第3次データ([jra-van.md](jra-van.md))と共通する処理は、`src/app/reader/JRA/` に切り出した。

| クラス | 内容 | JRA-VAN | JV-Data |
|---|---|---|---|
| `JraKaisaiTool` | 「年月日場回日R」から開催とレースの ID を作る。位置は `keyOffset` | `JravanKaisaiTool` (0) | `JvdataKaisaiTool` (11) |
| `JraRaceTool` | 開催の保存、グレード・種別・条件・コースなどのコードからレースへの変換(`setRaceCodes`)、障害のラップタイム | `JravanRaceTool` | `JvdataRaceTool` |
| `JraShussoubaTool` | 出走馬(馬、騎手、調教師、見習区分)の保存と、成績の共通項目(着順、異常区分、タイム、着差)。項目の位置は引数 | `JravanShussoubaTool` | `JvdataShussoubaTool` |
| `JraOddsHaitouTool` | オッズの読み取り(0.1 倍、`9999` は 999.9 倍、無投票などは保存しない)と保存 | `JravanOddsHaitouTool` | `JvdataOddsHaitouTool` |
| `JraTool` | 血統登録番号、騎手、調教師、競走馬の保存 | 〃 | 〃 |
| `JraTrack` | トラックコード → 芝ダート、右左、内外 | 〃 | 〃 |

- JV-Data のレコードは `JvdataRecord`(`id`、`length`、`save`)を継承する。レコード種別を足すときは、クラスを足して `JvData` の一覧に加える。
- レース詳細より先に馬毎レース情報・払戻・オッズが来てもよいように、`JvdataRaceTool.ensureRace` が開催とレースの行がなければ作る。レース詳細は項目が空白でも既存の値を消さない(`skipNull`)。
- 馬の同定、騎手・調教師の突き合わせ、人名の `MatchingKey` は JRA-VAN と同じ(馬は血統登録番号の下 8 桁、騎手と調教師は 5 桁のコード)。
- 繁殖登録番号は `Hanshokuba` 表で馬につなぐ(同じ馬に番号が複数あることがあるため、`Uma` の列にしない)。番号で見つからない祖先は、取り込み中の馬にすでにつないでいた親か、馬名で探す。別の繁殖登録番号が付いた馬は、血統登録番号が一致するときだけ同じ馬とみなす。
- 賞金は百円単位なので 100 倍して円にする。後 3 ハロンは 0.1 秒単位で、第3次データのような 60 秒の省略はない。
- 馬体重の `999`(計量不能)、増減差の `999`、後 3 ハロンの `999`、タイム差の `9999` は値なしにする。増減差は符号の列が別。
- 馬場状態は芝とダートがあるので、レースのトラックに合わせて選ぶ(障害の芝→ダートはダート)。
- 障害競走の後 3 ハロンは、実際には後 1 ハロンなので成績に入れない(第3次データと同じ扱い)。
- 馬齢は、血統登録番号がない馬(外国馬など)の年齢にだけ使う(2000 年以前は数え年なので 1 引く)。

## 既存コードの変更

- 共通化したため、`JravanTool` → `JraTool`、`JravanTrack` → `JraTrack`、`JravanKaisaiTool` の本体 → `JraKaisaiTool` に移した。`JravanRaceTool`・`JravanShussoubaTool`・`JravanOddsHaitouTool` は共通の部分を基底クラスに移し、位置を決めるだけにした。
- `DataToImport` の 1 行ずつ読む方法(レコード長 0)は、今まで使われておらず、次の問題があったので直した。
  - 1 行がバッファ(64KB)より長いと終わらなかった(3 連単のオッズは 83KB)。バッファを広げるようにした。
  - 最後の行に改行がないと終わらなかった。最後の行として読む。
  - 2 つ目のファイル以降で、前のファイルのバッファが残っていた。ファイルごとに作り直す。
- `RaceTool.saveRaceLapTime` に、読む件数(既定 18)を足した(JV-Data は 25)。
- コード表を JV-Data 4.9 に合わせた(`converters/`)。
  - グレード `L` を 4(L)に、`D`(グレードのない重賞)は 4 でなくなる。`L` は準重賞扱い。
  - トラックコード `25`〜`28`、馬記号の `jvdata`(JRDB と同じ番号)、東西所属の `jvdata`、騎手見習 `4`・`9`。
- `JravanUmaj` の馬記号を `toCodeFromJvData` にした(番号は同じ)。

## テスト

`test/jvdata.test.ts`。仕様書の CSV を読んで項目名から位置を引き(`test/spec/jvdata.ts`)、仕様書の位置にデータを置いたレコードを作って、実際の Importer に通す。

- 取り込み処理のレコード長が仕様書と一致する。コード表のコードが変換できる(未対応のコードがあれば失敗する)。
- レース詳細・馬毎レース情報・払戻(収録順を逆にしても同じ結果になる)、出馬表と削除・中止、空白の項目で既存の値を消さないこと、障害競走、ダートと 4.9 で増えたコード。
- オッズ(上限、無投票、発売前取消、中間オッズを読み飛ばすこと、83KB の 3 連単)。
- 競走馬・騎手・調教師・開催スケジュール。
- 改行のない最後の行、壊れたレコード、複数のファイル。
