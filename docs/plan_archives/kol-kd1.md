# KD1 の取り込み

KOL の第 1 世代フォーマット(KD1, 1997-11-13 の第 2-2 版)の取り込み処理。仕様書は [kol-spec/KD1/spec/k-siyou3.txt](kol-spec/KD1/spec/k-siyou3.txt)(`tmp/KOL/仕様書/旧データ/SIYOUSYO.LZH` を解凍したもの。Windows-932、CR LF)、取り込み処理は [src/app/reader/KOL/KD1/](../src/app/reader/KOL/KD1/)。見本データはない。

ファイル名は `KOL_SEI.DAT`、`KOL_SEI2.DAT`、`KOL_DEN.DAT`、`KOL_UMA.DAT`、`KOL_KIS.DAT`、`KOL_KYU.DAT`、`KOL_SYU.DAT`、`KOL_KET.DAT`(大文字小文字は区別しない)。

## KD2/KD3 との違い

項目の意味は KD2 と同じだが、並びが違う。KD2 のようにアドレスがずれるだけではなく、データの分け方が違う。

| データ | KD1 | KD2 |
|---|---|---|
| 競走成績 `sei` | レース + 出走馬 18 頭(3178)。19〜28 番は競走成績２ `sei2`(10 頭, 1342) | レース `sei1`(2756) と出走馬 `sei2`(474) が別ファイル |
| 出馬表 `den` | レース + 出走馬 18 頭(1537) | レース `den1`(779) と出走馬 `den2`(743) が別ファイル |
| 競走馬 `uma` | 2247。過去 5 走が 235 バイトずつ | 5166。過去 5 走が 590 バイトずつ(レース 151 + 出走馬 439) |
| 騎手 `kis` / 厩舎 `kyu` / 種牡馬 `syu` / 3代血統図 `ket` | 202 / 196 / 102 / 621 | 1729 / 1248 / 2010 / 839 |

KD1 にあって KD2 にない種別はない。KD1 にない種別は、予想オッズ `ods`、確定オッズ `kod`、コメント `com1`(KD2 の出馬表出走馬データにある調教、KD3 の ods2・kod2・kod3・sei3・ket5 も)。払戻は競走成績に入っている。

## 共通化の方法

KD1 のレコードを、KD2 のレコードに組み替えて、KD2/KD3 の取り込み処理(`KolKis` など)に渡す。KD1 専用の取り込み処理は、組み替えだけをする。

- 組み替えの表は [Kd1Layout.ts](../src/app/reader/KOL/KD1/Kd1Layout.ts)。`[KD1 のアドレス, 桁数, KD2 のアドレス]` の並びで、KD1 にない項目は空白のまま。
- 組み替えの部品は [Kd1Convert.ts](../src/app/reader/KOL/KD1/Kd1Convert.ts)。
- 競走成績・出馬表は、1 レコードをレース 1 つと出走馬(馬番がある分だけ)に分けて、`KolSei1Kd2`+`KolSei2Kd2`、`KolDen1Kd2`+`KolDen2Kd2` に渡す。
- [Importer](../src/app/Importer.ts) の並びは、KD1 の出馬表・競走成績・競走成績２の順(開催とレースが先にできている必要がある)。

## KD1 にない項目の補い方

| 項目 | 補い方 |
|---|---|
| 曜日コード(出馬表・競走成績) | 年月日から作る。祝日などの区別(1 バイト目)は分からないので 0 |
| 出馬表の平・障 | 条件カットが 0 (サラ障害)なら障害、数字ならそれ以外は平場。条件カットが空なら空 |
| 競走成績２の年月日 | レコードにない。先に取り込んだ開催から、場所・開催年・回次・日次で探す。見つからなければ、そのレコードは読み飛ばして警告を出す |
| 騎手名・厩舎名(出馬表・競走成績・競走馬の過去走) | KD1 には 8 バイトの短い名前しかない。騎手は短縮騎手名に、厩舎は短縮厩舎名と厩舎名の両方に入れる(厩舎名がないと調教師を登録しないため)。騎手の氏名は、騎手データで取り込まれる |
| 競走成績の予想 | 「出馬表の予想印」に入れる(「予想(本紙)」は空) |
| スピード指数 | 「レコード指数」に入れる |

## 取り込まれない項目

- 騎手・厩舎の本年度累計賞金と通算成績(KD2 とは桁数も並びも違い、取り込み処理も読んでいない)。
- 種牡馬の予約。競走成績の推定タイム。競走成績の出走馬ごとの中央・地方・外国、一・特、平・障、交流フラグ(KD2 ではレース側にあり、レース側から入れている)。
- 競走馬の現在の厩舎名(KD1 の競走馬データには厩舎コードだけがあり、名前がない)。そのため、競走馬データだけでは調教師が登録されない。出馬表・競走成績の出走馬から登録される。
- 3代血統図の祖先の馬コード(KD1 にない)。馬名だけで登録される。
- KD1 には KD2 の調教、解析、予想展開に当たるデータがない。

## テスト

[test/kol-kd1.test.ts](../test/kol-kd1.test.ts)。見本データがないので、次の 2 つで確かめる。

1. 仕様書との突き合わせ。KD1 の仕様書(テキスト)と KD2 の仕様書(HTML)の項目表だけを使う([test/spec/kd1.ts](../test/spec/kd1.ts))。
   - KD1 の項目表の長さが、見出しのバイト数と取り込み処理のレコード長に一致する。KD2 のレコード長も一致する。
   - 組み替えの表のすべての行が、KD1 の項目(または隙間のない項目の並び)と、KD2 の項目の中に収まり、名前も同じ(言い換えは表で明示)。
   - 組み替えない KD1 の項目が、上の「取り込まれない項目」だけである。
   - 組み替えで、別の項目が同じ場所に重ならない。
2. 項目を埋めた KD1 のレコードを作って、実際に取り込む。DB に、日付・曜日・レース条件・払戻・出走馬の成績・騎手・調教師・血統が入ることを確かめる。

KD1 の実データでは確かめていない。
